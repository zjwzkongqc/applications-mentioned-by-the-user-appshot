# GitHub Pages + Supabase Free：六人网球小组试运行

更新时间：2026-10-04。

本轮选择 **GitHub Pages + Supabase Free**。不购买 NAS、服务器或域名，不开通付费套餐。仓库其他文档中的 Neon 和国内服务器是历史备选，不是本轮执行目标。

## 现在完成了什么、没有完成什么

仓库已有 GitHub Pages 发布配置、Supabase Edge Function 构建代码、schema 5 数据结构及迁移工具。本轮新增独立的 Supabase 准备工作流，检查源码、运行自动化测试并打包后台源代码和 SQL；它不连接 Supabase、不读取部署密钥、不初始化数据库、不迁移数据，也不切换线上 Pages。

**工作流绿色只表示代码检查和打包成功，不等于 Supabase 部署成功，也不等于朋友已经能登录保存。** 原数据、线上访问、真实权限隔离和中国内地网络均须单独验收。测试中跳过的外部服务用例不计为真实环境通过。

## 群主当前只需完成账户连接

在 ChatGPT 中连接 Supabase 插件并完成官方账户授权。授权尚未完成时，不宣称已经创建或连接了项目。无需向聊天发送 Supabase 密码、数据库连接串、访问令牌或 service-role / secret key。

连接之后先检查组织、现有项目和套餐。仅使用确认处于 **Free** 套餐的组织；如无合适项目，再在免费额度允许的前提下准备专用测试项目。不得升级组织、绑定付费服务、购买域名或启用付费预览分支。若免费项目额度已满，停止并明确说明，不删除其他项目或自动升级。

六位球友只使用应用账号；Supabase 和 GitHub 管理账户由群主管理，不共享给球友。

## 当前代码的实际登录方式

现有应用使用自身的个人账号、设备会话和私密恢复码；以前的邮箱账号也有兼容入口。Supabase 适配承载业务 API、PostgreSQL 和私有图片存储，**不代表已经改成 Supabase Auth 的邮箱注册**。本轮先保留现有交互和账号归属，避免为了换托管平台而重建六个人的身份。

昵称不是身份凭据，邀请链接不是认领他人名片的凭据。后端必须验证会话、组员身份和记录归属；不能只在网页隐藏编辑按钮。未登录用户不得获取组内私密内容。现有群主的管理权限另行测试，不把管理员合法代改误报为普通成员越权。

## 部署与数据保护关卡

1. **免费项目确认**：核实账户授权、项目归属、Free 套餐与剩余额度。未核实不得部署。
2. **后台准备**：检查既有项目表结构后才运行 schema 迁移和部署 `tennis-api`。两份 SQL 均须保留：`20261004000000_tennis_schema.sql` 与 `20261004000001_tennis_schema5.sql`。不向有冲突或不完整表结构的项目盲目写入。
3. **保护接口**：保留应用级会话验证、成员权限、私有图片存储和数据库权限。当前应用使用自己的认证，Edge Function 的 `verify_jwt=false` 不是授权规则；不能据此开放数据库、照片或写入接口。
4. **迁移或初始化**：当前 handler 是现有应用的迁移接收端。没有有效迁移收据时，应继续返回未就绪；不能把健康检查的 HTTP 200 当成可用，因为它可能同时带有 `maintenance:true`。完整迁移必须包含现有 schema 5 的账户、会话、群权限、邀请、历史评分、记录、照片和审计。若确认要建立全新空群，也必须另行完成安全初始化，不能删除检查来伪造就绪。
5. **真实试用**：后述验收通过后，才修改 Pages 的后台地址。源代码提交、构建成功或 SQL 表已创建，均不能代替这一步。

原数据迁移需要私密的完整迁移快照。小组 NDJSON 资料备份不含账号凭据，不能替代完整后台迁移快照。私密快照、图片和凭据不得进入公共仓库或 Actions artifact。

## 最小验收：两名测试成员先跑通

| 检查 | 通过条件 |
| --- | --- |
| 独立登录 | A、B 各自建立或恢复自己的账号；不能只凭昵称取得对方身份 |
| 保存记录 | A 新增训练文字和月度六维评分，刷新后仍存在；待测与 0 分分开 |
| 跨设备读取 | A 在另一浏览器使用本人凭据恢复后，能看到同一份记录 |
| 修改隔离 | 普通成员 B 修改或删除 A 的记录被后端拒绝或不产生变化；再次读取确认 A 的数据未被改变 |
| 组内可见 | 仅获准加入小组的成员能查看组内内容；未登录、退组和其他组账号被拒绝 |
| 私有照片 | 未授权访问照片被拒绝；公开头像遵守成员主动公开和撤回的现有规则 |
| 手机直连 | 至少用实际中国内地手机网络测试打开、登录、保存与再次读取，不以服务器探测代替 |
| 备份与回退 | 备份可读取，旧后台保留到核验结束；切换失败能恢复原访问配置 |

测试数据要明显标注为测试，使用完按归属清理。不得把成员真实密码、恢复码、会话、照片或数据快照写入测试日志。

## 通过验收后才使用的 Pages 配置

在 GitHub Actions **Variables** 中使用：

- `TENNIS_API_BASE_URL`：已验证的 `https://<project-ref>.supabase.co`。
- `TENNIS_API_PATH_PREFIX`：`/functions/v1/tennis-api`。
- `TENNIS_MIGRATION_FROM_ORIGIN`、`TENNIS_MIGRATION_ID`：必须与已核验的后台迁移配置一致，不编造占位值。

这些公开地址不是部署授权。任何私密平台凭据只通过受保护的连接、平台 Secrets 或本地安全配置传递，不放入前端。

## 免费方案的限制

免费不等于无限额度、永久在线或国内网络保证。Supabase Free 存在闲置暂停及容量限制；群主需要能进入控制台恢复项目并保留备份。GitHub Pages 和 Supabase 在六位成员实际网络中的可用性仍须实测。本轮不配置制造虚假访问的保活任务，不自动开启付费扩容。
