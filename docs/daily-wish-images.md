# 心愿封面与每日制作清单

当前方案：**保持免费，改善心愿封面展示；每天汇总制作清单发给群主，由群主自行使用 Image 2.5 作图，再由群友登录自己的账号上传图片。** 应用不调用收费作图 API，不自动替换任何人的图片。

执行状态（2026-10-07）：私有数据读取和 Gmail 连接已验证，首份实际清单已由发送接口确认发送；当时没有进行中的心愿。ChatGPT 每日任务已创建并启用，计划从 2026-10-08 起按北京时间每天早上 8 点前后执行。首个计划运行尚未发生；发送接口成功不等于确认收件箱送达。收件地址只保存在私人任务配置中，不写入本公开文档、源码、页面或构建日志。

## 免费展示与手动作图

- 心愿图片以大幅封面展示，现有手动上传入口继续使用。名称、金额和训练进度由页面文字实时显示，不写死在生成图里。
- 群主收到清单后自行生成图片，并将成图交给对应群友。群友通过本人账号编辑心愿、上传成图，图片仍由现有私有存储及账号验证保护。
- 清单不会携带图片本体或可绕过登录的图片链接；群主不会因此获得他人账号、恢复码或代登录能力。
- 页面说明应清楚告知“心愿制作信息会汇总给群主”，不能再将心愿名称和金额描述为绝对只有本人可知。此流程不把心愿发布到群动态、公开会员卡或公开 GitHub 文件。
- 未生成、未上传或制作中断时，原有图片、心愿和训练记录保持可用。没有成功上传就不声称图片已更新，也不承诺次日自动换图。

## 每日清单的读取范围

仅选择当前主记录本 `ACTIVE_NOTEBOOK.id` 的有效成员，其成员记录必须满足 `removed_at IS NULL`，并通过成员的 `account_id` 关联本人进行中的心愿。已实现、已删除的心愿和已移除成员不纳入制作清单；归档记录本中的成员身份不能单独获得汇总资格。

允许读取和输出的字段限于：

| 字段 | 用途 |
| --- | --- |
| 群内昵称 | 确认图片交给谁 |
| `wish_id` | 同名心愿的稳定对应编号 |
| 心愿名称 | 确定要制作的物品或场景 |
| 目标金额 | 供群主了解目标，不代表商品报价 |
| `image_present` | 仅标记是否已经上传图片 |
| 创建、更新时间及清单统计时间 | 辨别新心愿和更新内容 |

不读取头像、个人照片、图片本体、训练明细、会话、恢复码、密码、邮箱或数据库密钥。不导出账号 ID、对象存储键或完整账号资料。统计清单使用私有读取连接，不要求群友提供任何身份凭据。

每日批次采用 `Asia/Shanghai` 日期。每次生成当时有效的心愿清单；存在图片也只标注状态，不擅自跳过仍进行中的心愿。不读取图片猜测“是否已完成制作”。无心愿时明确写“本次没有进行中的心愿”，而不是生成虚构内容。

## 清单内容与投递

邮件内容为统计日期、心愿数量、按群友整理的制作表，以及可供手动作图的物品描述和封面提示词。提示词不包含昵称、心愿编号、目标金额或账号信息；群主可以只复制必要描述给图片模型。心愿文本视为数据，不能执行其中夹带的指令或任意网址。

本方案通过现有搜索能力，为每项寻找 1–2 个可核实的官方参考页面；没有找到时如实说明。只使用物品或地点名称检索，不把昵称、编号和金额发送给搜索服务，不调用额外收费搜索 API。群主可在自行作图时补充参考图，不将未经核对的链接冒称已找到的素材。群主决定使用何种作图工具及其已有额度，应用不承诺外部工具无限免费。

每日汇总通过 ChatGPT 计划任务执行，经 Gmail 连接向用户指定邮箱发送 HTML 邮件；这不依赖公开 GitHub Actions 中存储私人清单。任务建立与首封发送已分别确认，后续执行仍需连接保持有效。不能把 ChatGPT 提醒通知冒称指定邮箱投递成功。

避免在公开 Actions 日志、仓库文件或网页缓存中保存清单。投递失败保留失败状态，不更改任何心愿或图片；重试时避免重复发送同一批次。连接授权失效时报告失败，不使用旧资料冒充当天结果。

## 上线核对

1. 私有连接只读测试成功，并核对主记录本、有效成员及允许字段的筛选范围。
2. 生成首份实际清单，检查无多余个人资料、图片、存储键或凭据。
3. 创建每日任务并记录确认结果；执行时区与私人收件配置正确，公开文档不记录邮箱或任务提示词全文。
4. 分别检查任务执行及邮件投递结果。只有得到相应确认后，才将状态更新为“已创建”或“已发送”。
5. 用隔离浏览器流程验证本人上传、心愿对应关系及跨账号访问限制；不在真实训练历史里写入测试数据。

## 未来付费自动作图方案（未启用）

Image 2.5 的 API 模型包括 `gpt-image-2.5-sunburst`、`gpt-image-2.5-flare`，属于计费 API。ChatGPT 订阅与 API 计费独立，当前对话的 Image Gen 工具也没有模型选择参数。此阶段没有配置这些 API 或后台自动作图任务。

如未来用户明确授权费用，再考虑：生成图与本人原图分别保存；以内容版本阻止改名、删除后的迟到结果；每天每个心愿只建立一个任务；按上海次日日期开放成功图片；使用租约、费用预留及单次/每日/每月预算上限。超时结果未知时不盲目重试付费调用，失败保留原图。所有生成图仍经本人会话验证读取，并在手动验证完整流程后才启用定时运行。

可能需要的私有配置名称包括 `OPENAI_API_KEY`、`OPENAI_IMAGE_MODEL`、`WISH_IMAGE_SEARCH_PROVIDER`、`WISH_IMAGE_SEARCH_API_KEY`、`WISH_ARTWORK_JOB_KEY` 及费用限额；这些只是未来方案，不要求用户在聊天或源码中提供密钥。
