## 六位球友怎样开始

群主先打开新入口，点击“开始使用 / 找回名片”，选择“第一次使用，填写昵称”。填写自己的昵称，点击“创建我的名片”，将随后显示的私密恢复码只保存给自己。

关闭恢复码窗口后，填写群名、群口号和自己的群昵称，点击“创建群小本本”。创建者自动成为该小组的管理员。点击“邀请搭子”，复制新站内生成的群邀请链接，发给其余五位朋友。

朋友必须通过这条群邀请进入，各自填写昵称、建立自己的名片、保存自己的恢复码，再点“加入这群搭子”。不要让每个人另建一个群，也不要共享群主的恢复码。邀请七天有效，过期由群主重新生成。

同一浏览器会记住自己的身份。换手机、换浏览器或清除网站数据后，选择“用恢复码找回我的名片”。微信内置浏览器与手机浏览器可能是不同的存储空间，需要用同一份本人恢复码恢复身份。

无须 ChatGPT、GitHub 或 Supabase 账号即可使用小本本；这两个管理平台的账号仅由群主保管。新站不会自动继承旧站的账号、评分或照片，旧恢复码不能当作新站身份凭据。

## 技术与隐私边界

- 前端：GitHub Pages 的独立 `/fresh/` 子路径。构建新路径前后比较原 `index.html` 和 `config.js` 的 SHA-256，确保不修改原输出。
- 后端：同一个已确认 Free 的 Supabase 项目，新增独立函数 `tennis-fresh`，不修改原 `tennis-api`。
- 数据库：独立 `tennis_fresh` schema，15 张应用表与 1 张新站状态表。新站状态明确为 `new-empty-app`，不是迁移成功回执。
- 照片：独立私有桶 `tennis-fresh-media`，单张服务端上限 2 MiB，JPEG/PNG/WebP；头像在网页里压缩后上传。
- 数据库连接：事务中固定使用 NOLOGIN、NOBYPASSRLS 的 `tennis_fresh_runner`，没有读取原 `public.accounts` 或写入原 `public.records` 的权限。匿名和普通 Supabase 浏览器角色不能直接访问新数据区。
- 账号：沿用应用自己的会话和恢复码机制，服务端验证成员关系及记录归属。Supabase 平台 JWT 检查关闭仅是为了使用这套自有认证，不是开放数据。
- 浏览器：新站有独立存储命名空间，不复制旧身份，不请求旧站迁移接口；业务请求不接受共享 Cookie 身份，只使用明确的应用会话头。
- 管理员：可管理小组、成员及按应用规则代改或删除，相关操作有审计。普通成员只能修改自己的内容。

平台密钥、数据库连接串、私密恢复码和真实照片不得放入 GitHub 源码、构建产物或测试日志。
